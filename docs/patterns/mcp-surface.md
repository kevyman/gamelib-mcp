# MCP surface: modules, widgets, tool consolidation

Why this exists: `main.py`'s tool signatures ARE the wire schema, and the
middleware/widget modules around them each encode a decision that is expensive
to rediscover (why a `ui://` URI is content-hashed, why the duplicate text
block is dropped, which CSP hosts a card needs). The root `CLAUDE.md` keeps a
one-line map plus the rules; the rationale and the measurements moved here on
2026-09-01. Decisions themselves live in ADR 0004 (tool surface) and ADR 0005
(spec currency) — this file holds the implementation notes around them.

## HTTP and response encoding

`http_admin.py` — origin-allowlist middleware + `/health`, `/admin/integrations*`, and `/ingest/{nonce}` (the cookie paste form; deliberately outside `/admin/` so a browser navigation needs no bearer header). `/mcp` is authenticated by FastMCP's OAuth provider, not this middleware.

`response_encoding.py` — `StructuredOnlyMiddleware` drops the duplicate text block FastMCP ships alongside `structuredContent` (the spec's backwards-compat SHOULD). Measured at 48% of all response bytes; both clients registered against prod (claude.ai AND chatgpt.com) were probed on 2026-07-27 and read `structuredContent`. `MCP_DUPLICATE_TEXT_CONTENT=1` restores spec-default behavior for a client that needs the text block — re-run ADR 0004's differential probe before assuming a new client is safe.

`session_ingest.py` — single-use cookie-paste links: in-memory nonce store (TTL 15 min, pop-on-success) + `/ingest/{nonce}` GET form / POST handler that dispatches to `tools.session_admin.set_*_session`. In-memory by design (single-user, single-process); a server restart invalidates outstanding links.

`MCP_ALLOWED_ORIGINS` — browser origins allowed on the HTTP surface; requests without an `Origin` header (native/CLI clients) still pass. The `create_session_ingest_link` paste form POSTs a same-origin `Origin`, so oauth mode auto-allowlists `MCP_PUBLIC_BASE_URL`'s origin, but local `disabled` mode must include `http://localhost:8000` here.

## The two MCP Apps widgets

Decision records: `docs/specs/2026-10-03-widget-ux-redesign.md` (structure: UX first, visual quality second, everything else third; no tool's wire contract changed except the additive `package.game.steam_appid`) and `docs/specs/2026-10-04-binder-design-language.md` (the visual language, "The Binder": every game is a collectible card; it supersedes the earlier spec's type-scale and restyle rules). This section is the current-state rules.

`apps.py` (game cards for `discover_games`/`get_game_detail`) and `apps_eval.py` (the evaluation card from `record_assessment`'s `package`; a package-less response renders a compact "Recorded/voided" note through the verdict label) are each ONE self-contained HTML string: no build step, no CDN, no runtime fetch beyond the allow-listed media hosts and the host's font `@font-face` rules. The `ui://` URI is content-hashed because hosts cache ui:// resources by URI (a stable URI left claude.ai stale across deploys). The hash alone is not enough on a LIVE connection: the host learns the new URI only from a fresh `tools/list`, which it fetches on connect, so after a deploy a client that stays connected keeps rendering the previous widget — CSS tweaks included. Reconnect the MCP server in the client (claude.ai: connector settings → disconnect/reconnect; Claude Desktop/Code: restart the connection) before concluding a widget change did not ship. All payload text goes through `textContent`, never `innerHTML` (tests pin it).

**Shared source, spliced verbatim.** `apps_shared.py` holds every block both widgets need (tokens, reset, chip/match-bar/skeleton/control CSS, the bridge, labels, numbers, score chip, display mode, model context, disclosure, notice, trailer stage, carousel). Constants carry their own indentation and are concatenated into each widget's HTML; reformatting one defeats the drift guard. `WidgetDriftTests` (`tests/test_apps_eval.py`) fails when 20 or more identical significant lines reappear in both widget files, so anything that large goes in `apps_shared.py`. `tests/test_apps_shared.py` runs the bridge in Node against a fake DOM (initialize, host-context merge, display mode, teardown), because a bridge bug is invisible to the HTML-marker tests.

**Theming.** Both widgets render on a `--gl-*` token layer defined once in `TOKENS_CSS` as `var(<host token>, <fallback>)`: Claude's `hostContext.styles.variables` win when present, `light-dark()` fallbacks keep ChatGPT/Goose/the offline preview rendering and follow `hostContext.theme` (via `color-scheme`) or `prefers-color-scheme` when there is no host. Widget CSS references `--gl-*` names only, so a palette change is one edit. The page is transparent (panels paint their own surface) and both resources register `AppConfig(prefers_border=False)`, so the card blends into the chat. Fonts arrive as `styles.css.fonts` injected into one `<style id="host-fonts">`; `https://assets.claude.ai` is in `resourceDomains` for them. Type is four sizes (20/16/14/12px) in three weights (400/600/800) plus the mono stack for numerals and the system serif for flavor text only, nothing under 12px; interactive elements get a 44px hit area on touch (32px otherwise, via an `::after` extension rather than a bigger visual), `:focus-visible` rings, `prefers-reduced-motion` honored.

**The Binder (design language).** Every game renders as a collectible card: a `.frame` whose border is a brushed-metal "rarity" gradient that always encodes ONE real quality tier (`.tier-good/ok/bad`, else a plain common frame) — the verdict on the evaluation card, the taste match in a match-sorted grid, the critic tier in a critic-sorted grid, your own rating on the detail card. Inside: an `.art` window with a 1px keyline and a static specular line, a 52px `.badge` carrying the lead number (OpenCritic / match % / your rating), a `.plate` (title, `No. <id>` card number, gap-separated sub spans — never middot strings), a `.stats` block with dotted leaders and mono values, diamond `.pips` (fit out of 3, rating out of 10), and a notched `.ribbon` for the verdict or status. Around the card: `.trait` rows (spark = for you, shield = weakness), `.ability` run-ins (STUDIO, MOMENT, AWARD …), serif `.flavor` text for craft notes and your own review, `.mini` cards in scroll-snap strips, pill `.btn`s (the only `radius-full` besides the badge). A grain layer (inline SVG `feTurbulence`, never a `data:` URL) sits on cards only. Tier colour appears on the border, ribbon, pips and badge ring and nowhere else. Motion (`MOTION_CSS`/`MOTION_JS`, durations in `docs/specs/assets/binder/MOTION.md`): one deal-in per card (300ms, ribbon stamps on with overshoot, pips light in sequence, leaders draw; everything at rest by 500ms), 40ms grid stagger capped at six, press feedback, skeleton→card resolve with a 60ms overlap, meter fills; a fixed 5° hover tilt + sheen only on fine pointers. Everything that moves sits inside `prefers-reduced-motion: no-preference`; the fallback is opacity-only. Never animated: text, numbers, covers, grain, colours.

**Bridge** (hand-rolled, MCP Apps spec 2026-01-26; the SDK stays out so the HTML stays dependency-free). Inbound: `ui/initialize` result (declares `availableDisplayModes: ["inline","fullscreen"]`; its `hostContext` is applied), `tool-input`, `tool-result`, `tool-cancelled`, `host-context-changed` (partial updates, merged not replaced), `resource-teardown` (replies `{}`). Unknown host requests answer -32601. Outbound from the views: `ui/request-display-mode`, `ui/update-model-context`, `ui/message`, `ui/open-link` (with a copyable-URL toast when the sandbox blocks it), `tools/call`. `ui/update-model-context` and `ui/message` are fire-and-forget and swallow method-not-found; `requestDisplayMode` falls back to the current mode on error or a 2.5s timeout, and `canFullscreen()` is true only when the host's `availableDisplayModes` contains `fullscreen`.

**Components rule.** One chip component for every score; color encodes the quality tier (good/ok/bad via `mcTier`/`ocTier`/`steamTier`/`craftTier`) and brand appears only in the label text, so a brand color never reads as a verdict (WCAG 1.4.1: every chip also has a text label, and the Steam phrase always accompanies its meter). Labels for platforms and verdicts are generated from `platforms_registry.PLATFORMS` and the `record_assessment` verdict literals; an unknown value is title-cased, never rendered raw; `LabelTests` fails when a registry name or verdict has no explicit label. Counts and hours go through the `NUMBERS_JS` helpers ("114k reviews", never "n=114k").

**Game cards (`apps.py`).** Grid: a set line rebuilt from the tool input ("8 of 2090", then the facets — sort, vibes, "unplayed", "≤ 10h" — as sentence-case lozenges), then a page of small frame cards (two columns on a phone, three from 560px, four in fullscreen). Each card is one `<button class="frame frame-s">` whose tier is the taste match (≥70 good, 50–69 ok) or, sorted by critics or value, the critic tier: the art with the badge (match %, or the critic score — `leadCritic` in `SCORE_CHIP_JS`, OpenCritic else Metacritic, the one precedence every critic badge and critic tier in both widgets reads), a slim art-edge ribbon only for TOP MATCH / CRITICS' PICK, the plate (title; hours, the platform lozenge and `No. N` on one sub line), at most two score chips, up to three matched tags as diamond-bulleted spans. Footer actions are "Show next N" (a chat message, only when `has_more`) and "Open full screen" (only when `canFullscreen()`); rank numbers render only when the payload carries `offset`. A card tap hands selection back to the model rather than opening a widget overlay (there is none any more): it always calls `ui/update-model-context` with the selected game, then opens the live `get_game_detail(media=true)` in fullscreen when the host offers it, or sends a chat message ("Show me {name}") when it does not. Detail mode is one big frame — tier from his rating, else the critic tier; badge "8 /10" YOUR RATING; the status ribbon on the art's edge; the plate (studio, year, owned-platform lozenges, `No. <id>`); stats (PLAYED, LAST, LENGTH — or MAIN STORY / MAIN + EXTRAS / COMPLETIONIST when the longer HowLongToBeat lengths are known, the one stat block allowed seven rows — PAID, the score chips, RATING pips) — then the ground: the 3-line description, his review as flavor text, award run-ins, one line of genres then tags (eight at most), the media reel (trailer hero, screenshot strip, single-slot lightbox), IN YOUR LIBRARY and FROM THE STUDIO mini strips, any enrichment notice ("Not fetched — Steam: no app id"), and the actions row (the store link; nothing sits behind a breakdown any more). FROM THE STUDIO is one shared builder (`studioStrip` in `PEDIGREE_JS`, both widgets): the lead developer, "est. 1997" and the publisher as spans, co-developers as a muted "with …" line, then the pedigree `timeline` (5 before, 3 after) oldest to newest with a 1px hairline at this game's year — and, when `timeline.after_gap` is set, a muted 12px "earlier releases not fetched" note between the hairline and the after group. From 560px the frame stands left of the ground. Similar uses the library's own tag similarity, not a provider list. Lozenges carry `PLATFORM_SHORT_LABELS` ("Epic", "EA", "Ubisoft") so the sub line stays one row; the full `PLATFORM_LABELS` names stay for prose and aria-labels. CSP: the two cover-art hosts plus the media hosts and youtube-nocookie frame domain also listed for the evaluation card, and `assets.claude.ai`.

**Evaluation card (`apps_eval.py`).** The frame IS the verdict: its tier is the verdict's (buy now / play what you own good, wishlist / try demo ok, skip bad); the art window carries the critic badge (OpenCritic, else Metacritic); the plate names the game, its studio, year, a short platform lozenge and `No. <assessment id>`; the stats are the call (pace, price seen, target, length, paid, fit pips); the straddling ribbon states the verdict in words with its one note ("wait for ~€40"). The ground follows in reading order: candidate / ownership line, summary, WEAKNESS traits, pitch, the why-care abilities, the craft note as flavor text, the media reel, the IN YOUR LIBRARY strip, at most two actions — "Full breakdown" (fullscreen, else a disclosure in place) and "Store page" (only when `package.game.steam_appid` resolves) — the provenance line and a single failure notice. The breakdown is eyebrow sections on the ground, never boxed panels: FOR YOU IF / NOT FOR YOU IF trait columns, GROUNDED IN YOUR HISTORY (anchor minis with his rating as pips), LINEAGE columns of minis with their notes, FROM THE STUDIO (the shared timeline strip above), PAST VERDICTS (a small ledger). Each failure is one plain sentence ("Not enough tags yet to find similar games in your library."), the server's string on hover only; the too-few-tags note is not sent for a candidate dated in the future (an undated one keeps it). A package-less response is a note card: a horizontal small frame with a slim ribbon ("Recorded" in the verdict's tier, or a tier-none "Voided") and a one-line caption. Dates go through the shared helpers: `dayMonthYear` ("3 Oct 2026") for provenance, the ledger and note captions, `monthYear` ("Sep 2022") for the detail card's LAST row. CSP additionally lists the Steam `shared.*`/`cdn.akamai` image hosts, `i.ytimg.com` posters, and `frame_domains=["https://www.youtube-nocookie.com"]` (per the MCP Apps spec, resourceDomains feeds media-src too, so the inline `<video>` trailer relies on that).

**Measured heights** (`render_all_previews.sh`, dark theme, inline unless noted): the evaluation card, sample 5 (Wolverine), is 1,715px at 360 and 1,339px at 760; sample 0 (Hades II) 1,552 / 1,353. The game-cards grid (8 cards) is 1,757 / 1,607, and 946px in fullscreen at 760. The detail card (Ghost of Tsushima, with media) is 1,784 / 1,034.

**Known host caveat.** Claude restricts `frameDomains` pending security review, so the YouTube-embed trailer branch may not render inside Claude (the mp4 branch does). Do not "fix" this in the widget; the poster plus link-out fallback is the designed degradation.

**Previews** (no MCP host needed): `scripts/preview_game_cards.py {grid,detail}` and `scripts/preview_eval_card.py [sample]`. Shared flags: `--theme light|dark` injects Claude's token table as `window.__PREVIEW_HOST_CONTEXT__` (from `scripts/preview_host_context.py`, which carries the published style variables), `--touch` simulates a touch device. Cards add `--display inline|fullscreen`, `--sample-media` (offline media/similar/studio sections) and `--from-json PATH` (render a saved tool payload from `scripts/preview_samples/` with no database; `--tool-input` sets the simulated arguments); eval adds `--fullscreen` and `--expanded` (open the full breakdown on load). Without `--theme` the page renders on the fallbacks. `scripts/screenshot_widgets.mjs` shoots preview pages in headless Chromium (Playwright, not a project dependency) at the given widths and prints each page's measured height; `--img-cache DIR` serves images offline. `scripts/render_all_previews.sh` (`OUT=`, `IMG_CACHE=`) renders every variant — eval samples 0–5 in both themes, the fullscreen and expanded eval variants, grid and detail from the saved payloads — screenshots them at 360 and 760 (fullscreen at 760) and ends with the height table.

## Skills over MCP

`skill_resources.py` — serves the `skills/` gaming skills (see below) as `skill://<skill-name>/<path>` MCP resources plus a `skill://index.json` discovery index, in the SEP-2640 URI shape (ADR 0006), AND backs the `get_skill` tool (decision 4b) — the same bytes for hosts whose model can't call `resources/read` (claude.ai custom connectors surface only tools to the model). Both surfaces share one per-request disk scan, so an edited skill file needs no restart and the two can't drift; a missing/empty `skills/` dir logs a warning and registers no resources rather than failing startup (the tool then serves an empty index with a note). `scripts/package_skills.py` builds installable trigger stubs (canonical frontmatter + a fetch-via-`get_skill` body) and claude.ai Skills-upload zips from the canonical folders.

`skills/` (repo root, sibling of `gamelib_mcp/`) is the canonical home of the client-side gaming skills (`game-quality`, `backlog-triage`) per ADR 0006 — they version with this repo and are served read-only via `skill_resources.py`; `~/.claude/skills` and claude.ai Skills installs are downstream copies, never the source of truth.

## Platform registry

`platforms_registry.py`: the single registry of platforms. All platform lists/aliases derive from it. Sync/inspector functions are `(module, attr)` strings resolved lazily (no import cycles), preferring names bound on a caller-supplied namespace — which keeps the `patch("gamelib_mcp.tools.admin.sync_epic", ...)` test pattern working. Adding a platform = `data/<platform>.py` + one `PlatformSpec` (+ an inspector probe if it should appear in integration status).

## Bounded responses

**Bounded responses**: every response field whose length scales with library size must carry a cap, the true total, and a truncation flag (`get_stats(report="platforms")`'s `overlap_games`/`overlap_count`/`overlap_truncated`; `get_wishlist`'s `limit`/`total_matches`/`has_more`). Schema is paid once per connect; responses are paid per call and were measured at 2.5x the whole tool surface across one short session. `tests/test_tool_dispatch.py::ResponseSizeGuardTests` walks real responses and fails on any list over its documented cap — add new read paths there.

## One tool per operation, not per arity (ADR 0004)

**One tool per operation, not per arity** (ADR 0004): `main.py` registers 33 MCP tools over ~50 implementation functions in `tools/`. A `@mcp.tool` wrapper is a thin mode-dispatcher; impls keep their own names, signatures, and unit tests, which is why consolidating the wire surface touched almost no test. Conventions a new tool must follow: bulk is `items=[...]` on the single-item tool (never a second `*_batch` tool), verb families take an `action`/`report` selector, a merged tool inherits the STRICTEST annotation it absorbs, merged response models declare every field optional with comments naming which mode fills what, and a multi-mode tool validates the inputs of EVERY selected mode before running the first one (`admin.validate_sync_platforms` — `sync` starts the fire-and-forget library target first, so a later target's rejection would otherwise error on a sync already in flight). Read docs/adr/0004-consolidated-tool-surface.md — especially its "Rejected" list — before merging or adding a tool.

## MCP spec currency (ADR 0005)

**MCP spec currency** (ADR 0005): track the latest STABLE FastMCP/mcp SDKs (protocol 2025-11-25 today); adopt a new spec revision only once a stable SDK ships it AND a registered client speaks it — never pre-release SDKs in prod. The app-layer rule that keeps that bump cheap: no tool may depend on per-connection state, `tools/list` never varies per-connection, and cross-call state is explicit handles (`sync`'s ack + `get_sync_status`). The 2026-07-28 migration checklist (SDK bump, drop ctx-logging, tasks extension, apps bridge version, ttlMs values, re-probe clients) lives in docs/adr/0005-mcp-2026-07-28-readiness.md — read it before bumping fastmcp past 3.x or adding protocol-level features.
