# `gamelib_mcp/data/` — fetching and caching (all async)

- `db/`: SQLite package. `__init__.py` holds connection/migration/init and re-exports everything — `gamelib_mcp.data.db.<name>` is the stable public API. Submodules: `schema.py`, `migrations.py` (the whole `_MIGRATION_STEPS` chain + schema-state detection; `init_db`/`migrate_db`/`SCHEMA_VERSION` stay on the façade, which re-exports only `_run_migrations`), `claims.py` (enrichment claiming), `queries.py`, `upserts.py`, `affinity.py`, `fuzzy.py`. `retry_on_write_contention` (in `__init__.py`) decorates the idempotent sync writers in `upserts.py`; see the write-contention pattern in the root CLAUDE.md before adding or removing one — the retry exists for `SQLITE_BUSY_SNAPSHOT`, which `busy_timeout` cannot help with, and is only safe on an operation whose failed attempt committed nothing.
- `enrich_bg.py`: background enrichment orchestration.
- Providers: `steam_xml.py` (GetOwnedGames — adds/updates only, never deletes; clears the `delisted` flag for appids the API returns again), `steam_session.py` (mints short-lived `steamLoginSecure` store cookies from the long-lived `steamRefresh_steam` refresh token via `login.steampowered.com/jwt/finalizelogin` → per-domain transfer POSTs; shared by the purchase importer and license audit through `load_steam_web_cookies`, with fallback to static `steam_store` cookies when no refresh token is stored), `steam_licenses.py` (license audit: `dynamicstore/userdata` rgOwnedApps diffed against the library — GetOwnedGames omits some retired apps the account still owns; classifies gaps via appdetails, names retired games via SteamSpy, mints owned rows flagged `delisted=1`; per-appid outcomes persist in the `steam_license_audit` meta key), `steam_store.py` (7-day cache), `steam_reviews.py`, `hltb.py` (30-day), `protondb.py` (30-day), `backloggd.py`, `igdb.py` (name resolution order: IGDB `search`, then an EXACT `where name = "…"` equality lookup — search is a relevance index and returns zero for titles IGDB demonstrably holds, e.g. "The Forest" (7504) — then the widening query ladder; an ambiguous exact-name hit (two real games share a name) is refused, never ranked), `opencritic.py`, `metacritic.py`, `steamspy.py`, `itad.py`.
- Platform syncs: `epic.py`, `gog.py`, `nintendo.py`, `psn.py`, `xbox.py` (+ `title_normalization.py`). Every one of them calls `upsert_game_platform(..., from_source=True)` — that flag is what stamps `last_seen_in_source` and what re-owns an unpinned row, and it must stay exclusive to sync paths (a manual tool passing it would claim the source said something it didn't).
- `last_played.py`: the cross-platform last-played contract + `coerce_last_played_date` (unix epoch or ISO-8601 → `YYYY-MM-DD`, rejecting sentinels: epoch ≤ 0, pre-1980, `bool`). Every source feeding `game_platforms.last_played` goes through it. Coverage is best-effort by design — psn/switch2 always, steam via `rtime_last_played` (also backfilled by migration v35), xbox/epic by probing undocumented payload keys, gog never. A source that stops reporting it must degrade to NULL, never block an ownership sync. NULL is *unknown*, and `tools/history.py`'s gate treats it as such rather than as "not played". `record_play_history_snapshots` **copies the value onto each snapshot** (`play_history.last_played`, v36) instead of letting readers join the live column: `game_platforms.last_played` is mutable, so a historical window's answer would change the next time the game was launched. A snapshot is an immutable observation and carries what was true when it was taken.
- **PSN is per-SKU, the library is per-game** (`psn.py`): one `ps5` platform covers both consoles, and PSN's gamelist returns a separate entry — own title id, own `play_duration` — for each SKU of a cross-gen title (`CUSA…` PS4, `PPSA…` PS5, sometimes one PPSA per region). They all resolve to one games row, `game_platforms` is `UNIQUE(game_id, platform)`, and `upsert_game_platform` merges playtime with `COALESCE(excluded, existing)` — so writing per SKU meant last-writer-wins, and because PSN sorts by last-played DESC the stalest SKU wrote last (prod lost AC Valhalla's and Ghost of Tsushima's PS5 hours to their PS4 entries, `last_played` regressing with them). `sync_psn` therefore resolves in one pass and writes in a second: `_SkuAggregate` sums playtime across a game's SKUs, takes `max(last_played)`, and marks the most-played SKU `is_primary`. Folding is gated on `normalize_edition_comparison_title` equality **between SKU names** (detection never keys on the stored library name, which a user may have renamed): "Ghost of Tsushima DIRECTOR'S CUT" folds into "Ghost of Tsushima", but "Ratchet & Clank" does not fold into "Ratchet & Clank: Rift Apart" — one of them gets its own games row. **Which one keeps the canonical row is decided by the row's stored name, never by arrival order** — PSN's ordering is last-played, so it flips the moment the user plays the other SKU, and forking whichever SKU happened to arrive second would hand the canonical row (name, cover, IGDB link, ratings, acquisition) to the intruder half the time. The SKU whose name agrees with the row stays; the other is evicted onto a minted row — cheap because pass 1 persists no platform rows, so an aggregate can still be moved. That auto-split is safe only here, where the source reports playtime per SKU so there is nothing to re-attribute; the general no-automatic-split rule still holds elsewhere. `added`/`matched` count games, and `merged_skus` reports the extra SKUs folded in. Xbox uses OpenXBL (`OPENXBL_API_KEY`, optional `OPENXBL_XUID`); ownership = title history (documented approximation), playtime best-effort (`None` when unavailable, like GOG).
- Wishlists: `steam_wishlist.py` (official `IWishlistService/GetWishlist`; returns appid only, so unowned titles come from `steam_store.fetch_app_name`) and `dekudeals.py` (shared-wishlist `.json` export: `{"items": [{"name", "link", "added_at"}]}` — no NSUID anywhere, so fuzzy name matching is the only bridge; `added_at` becomes `wishlisted_at`). `dekudeals.py` also scrapes wishlist and search-page prices (shared selectors).
- Nintendo switch2 uses two complementary sources: `nintendo.py` = **ownership** (VGCS cookies, no playtime); `nintendo_pctl.py` = **playtime** (Parental Controls API, ownership-agnostic — titles played under another account get auto-added as owned). Daily summaries accumulate idempotently in `nintendo_play_summary`; switch2 total playtime is their `SUM`. Forward-only — no retroactive history exists; pre-tracking playtime is user-backfilled via `set_switch2_playtime_baseline` (a sentinel `manual-baseline` device row, excluded from `last_played`/window math). Nintendo title ids are normalized to uppercase at ingest (`data/db/__init__.py::normalize_identifier_value`, applied by `upsert_game_platform_identifier` and `upsert_nintendo_play_summary`), so every comparison between `game_platform_identifiers.identifier_value` and `nintendo_play_summary.application_id` is plain equality — no `UPPER(x) = UPPER(y)` at read time.
- `purchases/`: per-store purchase-history importers (eshop `nintendo_ec.py`, `epic_orders.py`, `humble.py`, `gog_orders.py`, `steam_history.py`) behind `import_purchases` — each exposes `fetch_*(*, transport=None) -> (records, skipped)` and is registered in `PURCHASE_IMPORTERS`; GOG reuses the lgogdownloader session, Steam scrapes the logged-in licenses/history store pages, Epic reads the account website's `ajaxGetOrderHistory` (browser cookies via `provider="epic"` — Legendary's launcher session can't see orders; the real fetch path impersonates a browser via curl_cffi `firefox135` because Cloudflare challenges non-browser TLS fingerprints from the datacenter IP — Chrome profiles are detected, and a distinct `_CHALLENGE_ERROR` explains a challenge 403 is not a cookie problem; zero-amount weekly-giveaway claims land as `purchase_source="free"`, in-game currency packs — V-Bucks/credits/points, name-detected — land in `skipped`, and the order's explicit ISO currency outranks ambiguous "$" symbols). Humble reads order detail from the BULK endpoint (`/api/v1/orders`, repeated `gamekeys` params, chunks of 35, per-order fallback on an unexpected answer): one request per order does not scale with account age — several hundred sequential round trips ran past the caller's timeout, so the source silently stopped completing. A Humble Steam key also carries `steam_app_id`, which becomes the record's `store_identifier` (Steam keys ONLY — the value is meaningless on a GOG/Origin key and `IDENTIFIER_TYPES["humble"]` reads it as a steam_appid). That is the one exact identity signal in an order: without it an edition-titled key ("Disco Elysium - The Final Cut") matches by alias onto a same-game edition row that owns the title but not the Steam copy, and the acquisition lands in `no_platform_row` and is discarded. A key Humble reports no `redeemed_key_val` for is usually unredeemed (already owned elsewhere, or held to gift), so its record is RESTRICTED — `PurchaseRecord.mint_allowed=False`, meaning it may FILL a platform row an ownership sync already confirmed but may never MINT a game or platform row. `import_purchases` enforces that with `_source_confirmed_items` (the row must carry a `last_seen_in_source` stamp — switching creation off only proves the row EXISTS, and a row can exist because a previous import minted it) plus a second batch pass with creation off, reporting everything else in `unconfirmed_unmatched`; a restricted record is also withheld from `bundles_needing_split`, since `split_bundle_acquisition` creates a platform row per matched constituent unconditionally. Not dropped, because the signal is weak both ways: `is_expired` is deliberately NOT consulted (the expiry date is a deadline for redeeming and passes either way — Humble reports Death Stranding Director's Cut from Choice April 2023 as expired though Steam Support confirmed the 2023-04-05 activation), and Humble stops reporting a value for expired keys whether or not they were used. Every key keeps its share of the order split. That gate is armed only when the WHOLE history holds at least one revealed key: if Humble stops sending the field, reading it as "every key unredeemed" would import nothing while reporting success, so its absence is reported instead of assumed.
- `media.py`: on-demand trailer/screenshot/similar-games media for the cards (`get_game_media(*, steam_appid, igdb_id, name)`). Steam path: appdetails `screenshots,movies,short_description` filter groups; appdetails now serves only DASH/HLS manifests, so the trailer is the CONSTRUCTED legacy mp4 (`cdn.cloudflare.steamstatic.com/steam/apps/<movie_id>/movie480.mp4` + `movie_max`), HEAD-gated before use because that surface is undocumented and Valve could drop it — a 404 loses the hero, never the screenshots. IGDB path (reuses igdb.py's token/gate/retry stack): screenshots/YouTube video ids/summary/similar_games; exact-name resolution when no ids, ambiguity refused, NEVER written back to `games.igdb_id`. Similar games are IGDB-only, so a Steam-sourced result borrows them from the game's IGDB record; the media block itself stays whole-source. Also fetches the studio **pedigree**: involved_companies (developer = developer AND NOT porting AND NOT supporting; publisher name only) + `hypes`, with the company's catalog from ONE bounded games-endpoint query (`limit 30`, per-company meta-KV cache 30d) — never `company.developed` expansion, which is unbounded for an EA/Ubisoft; a catalog over 25 titles trips the big-studio damper (`big_catalog`, header-only downstream). Steam-sourced results borrow `pedigree_raw` like `similar_raw`. Meta-KV cached: 7d payloads (`game_media:v2:` — bump `MEDIA_CACHE_VERSION` when the payload shape grows), 30d name mappings, 24h misses, stale served on fetch failure, failures never cached.
- `scrape_config.py` / `scrape_validate.py` / `scrape_fixtures/`: the healable-scraper layer (pattern below).
