# `gamelib_mcp/tools/` — MCP tool handlers

**Wire surface vs. implementations (ADR 0004).** `main.py` registers 30 tools; this package holds ~50 implementation functions. The mapping is deliberately not 1:1 — a `@mcp.tool` wrapper is a thin mode-dispatcher over impls that keep their own names, signatures, and unit tests. Two consolidations to keep in mind when reading the bullets below:

- **`*_batch` impls are still here, but are no longer their own MCP tools.** `search_games_batch`, `get_game_details_batch`, `rate_games_batch`, `add_games_to_platform_batch`, `update_games_batch`, `set_playtime_batch`, `set_acquisitions_batch`, `merge_games_batch`, `delete_games_batch` are reached by passing `items=[...]` (or `queries=[...]` for search) to the corresponding single-item tool. Three params carry a **mode-dependent default** that preserves the old two-tool behavior exactly, and must stay that way: `get_game_detail(enrich=None)` → True single / False bulk; `set_acquisition(overwrite=None)` and `set_acquisition(create_platform_row=None)` → True single / False bulk. Adding a fourth is a smell, not a precedent.
- **Report/verb families collapsed too.** `get_stats(report=…)` fans out to `stats.get_backlog_stats`, `platforms.get_platform_breakdown`, `ratings.get_taste_profile`, `acquisition.get_spending_stats`, `series.get_series_breakdown`. `sync(targets=…)` fans out to `admin.refresh_library`, `admin.sync_wishlist`, `ratings.sync_ratings`. `get_wishlist(with_prices=True)` → `deals.get_wishlist_deals`. `query_library()` with no sql → `query.get_db_schema`. `get_scrape_config(diagnose=True)` → `scrape_admin.diagnose_scrape`; `manage_scrape_config(action=…)` → propose/approve/rollback.

- `library.py`: search_games, search_games_batch (nested-content fallback when nothing matches; an EXACT normalized name match always surfaces even when the row is nested — hidden exact matches tempt create_missing callers into minting duplicates), get_library_stats (content filter: games/addons/all; always-on addons summary block)
- `batch.py`: shared plumbing for the bulk (`items=`) mode (item-cap/empty checks, per-item error isolation, frozen key-set validation — an unknown key that IS a field on another tool, e.g. `delisted`/`playtime_minutes` passed to a games-table bulk call, gets that tool named in the error via `_KEY_HOMES`). Convention: items are plain dicts; only empty/over-cap raise; everything else is a per-item `status` result preserving input order; bulk calls defer `recompute_tag_affinity` to one call after the loop.
- `detail.py`: get_game_detail (triggers lazy enrichment; returns related_content children with ownership/prices/acquisition, parent link for nested rows, dlc_ownership for Steam base games), get_game_details_batch (max 50; enrichment always skipped — cached fields only, `enrichment: "skipped"` in the response)
- `discover.py`: discover_games (vibe filters + taste/critic/value ranking)
- `ratings.py`: sync_ratings, rate_game, rate_games_batch (writes all ratings, then one deferred affinity recompute), get_ratings, get_taste_profile
- `stats.py`: get_backlog_stats (reached as `get_stats(report="backlog")`)
- `series.py`: get_series_breakdown (reached as `get_stats(report="series")` — the only paginated report), discover_series_gaps (still its own tool; it's the network one)
- `completion.py`: suggest_completion_status — read-only heuristic, never writes; no longer its own MCP tool (ADR 0004), it now backs `check_library`'s `completion.unclassified` check, whose `suggested_action` hands the confirmation to update_game
- `deals.py`: get_wishlist_deals (reached as `get_wishlist(with_prices=True)`) — honors `hardware_preference` with a `preference_override_ratio` escape hatch; 12h TTL, `refresh=True` forces live fetch
- `history.py`: get_play_history (see playtime-history pattern below)
- `admin.py`: refresh_library, sync_wishlist, audit_steam_licenses (heals ownership from the Steam account license list — GetOwnedGames omits some retired apps, and never-launched ones; `delisted=1` is set ONLY when the store lookup itself fails, never merely because the owned-games API skipped the app; minted rows report their new `game_id`; also auto-runs capped after each Steam refresh when a store session is stored; a `mint=False` mode backs `check_library`'s `ownership.license_gap` report path without minting), split_game (inverse of merge_games), merge_games (transfers everything the source row carries — platforms/identifiers/enrichment/ratings/series/aliases/play_history **plus** game_wishlist and game_prices, which would otherwise FK-cascade away with the source; children re-point to the target, and a nested target that absorbs its parent or inherits children is promoted to primary — the phantom-edition-parent remediation), merge_games_batch (many source→target pairs; ids consumed earlier in the batch report `stale_id` — in dry_run too), delete_game (two-step: `confirm=False` previews row counts, `confirm=True` erases the game + all dependents; refuses a parent of nested content; prefer merge_games to consolidate a duplicate), delete_games_batch (same two-step; parent-of-nested items land `refused` without aborting the rest, preview totals match confirm), set_nintendo_pctl_session, create_session_ingest_link (mints a single-use `/ingest/{nonce}` browser link so cookies are pasted in a form, not the chat; delegates to `session_ingest.mint_ingest_link`). The detector functions formerly exposed as their own MCP tools — detect_farmed_games, detect_collapsed_games, detect_cross_platform_collapses, detect_orphan_games (phantom_parents/orphans split), detect_stranded_duplicates, detect_misclassified_dlc (buckets: inconsistent_primary_nested > nested_parent > needs_parent > wrong_parent_suspect > purchase_minted_suspect > addon_name_pattern + steam_type_mismatch probe), revalidate_igdb_matches — remain here UNCHANGED (same logic, same unit tests) and are **no longer MCP tools themselves**; `tools/checks.py`'s `check_library` registry adapts each one's output into a finding (see the checks.py bullet below and ADR 0003). The cookie-session save functions sharing `_save_session_cookies` — `set_nintendo_session`, `set_epic_session`, `set_humble_session`, `set_steam_refresh_session` (preferred Steam path — the long-lived `steamRefresh_steam` token), `set_steam_store_session` (legacy short-lived fallback) — are similarly **no longer MCP tools**; they remain as internal helpers that `session_ingest` dispatches to by name (registry `setter_name`), so cookies only ever arrive through the browser paste form
- `checks.py`: `check_library` — one consolidated registry (`CHECKS: dict[str, CheckSpec]`) of data-integrity checks, replacing the 8 `detect_*`/`audit_steam_licenses`/`revalidate_igdb_matches` tools above with adapters over their unchanged functions, plus 11 new offline-only checks (identity/nesting/ownership/wishlist/playtime/spend/enrich/sync). Check ids are `category.name` and a frozen API — `main.py`'s `check_library` docstring lists every one, enforced by a drift-guard test (`tests/test_tool_registration.py`). `checks=None` (default) runs every check with `network=None`; a network check (`igdb` / `steam+steamspy`) only runs when named explicitly or `include_network=True`, landing in `checks_skipped` (not raising) when unconfigured. `include_network` widens ONLY the default selection — with an explicit `checks` list the run set is exactly what it names (naming a network check is sufficient). Report-only: every finding's `suggested_action` names an existing repair tool (merge_games/update_game/split_game/delete_game/set_acquisition/refresh_library/…) or is `None` with a human note folded into the message; only three checks ever write, gated behind `apply` naming their id (`playtime.farming`, `extid.igdb_drift`, `ownership.license_gap`). Suppressions (`suppress`/`unsuppress`, `{check, game_id}` pairs, persisted in `meta`) post-filter findings — tool config, not library data. Supersession stance (three-way split, one bucket per phantom parent): no owned child → `nesting.phantom_parent`; an owned EDITION child (content_type `edition`, or an edition-suffixed name under `normalize_edition_comparison_title`) → `nesting.superseded_base`, suggesting `merge_games` into the heir (most playtime, then most store identifiers, then lowest id) so the edition becomes canonical and the empty shell disappears; owned DLC/expansions only → `ownership.dlc_without_base`, informational and never a merge (owning DLC without its base game is a real state, and merging would rename the base row to a DLC title). `extid.igdb_drift` reports only `drift_kind="wrong_entity"`: a library name that is the IGDB name plus an edition suffix ("Nioh 2 - The Complete Edition" → "Nioh 2") is a correct link, counted as `edition_suffix_count` and never reset unless `options.include_edition_suffix`; nor is a link IGDB's own `external_games` maps the row's Steam appid to (`drift_kind="store_authoritative"`) — `backfill_missing_games` applies that mapping ahead of any name check, so resetting one only makes the next backfill re-pin it. Those still report, as a NOTICE suggesting `update_game(igdb_id=…)`: the mapping is authoritative but not always right (prod: Steam appid 212680 maps to 178437 "Faster than light?", a junk duplicate, while the real FTL record exists separately), and a hand pin is the only repair that outranks it. An apply also clears the unpinned `cover_image_id`, which is the wrong game's art. `spend.duplicate_purchase` skips same-family pairs sharing a `bundle_name` — that shape IS what split_bundle_acquisition writes. See docs/adr/0003-consolidated-validation-checks.md (plus its first-sweep amendment).
- `platforms.py`: get_platform_breakdown (games vs addons split, plus owned_addons per platform; `overlap_games` is CAPPED at `overlap_limit` — it was the one response field that grew linearly with the library, 428 entries / 98% of the report at ~3k owned rows — with `overlap_count` the true total and `overlap_truncated` the flag), get_wishlist (content_type labels each item; paginated via limit/offset for the same reason, with total_matches/has_more), set_hardware_preference, add_game_to_platform (targets a row by `name` — EXACT match, mints on a miss, so a typo makes a phantom row — or by `game_id`, which only ever edits (unknown id = error): prefer game_id when correcting. `owned=False` = manual wishlist entry — the only path for PSN; its `playtime_minutes` is NOT sync-protected — use set_playtime to pin; `delisted=True/False` is the only manual write path for that column and IS sync-protected, pinned in `game_platforms.manual_overrides` and released via `set_playtime(clear=["delisted"])`), add_games_to_platform_batch, update_game (manual edits recorded in `games.manual_overrides`; parent_game_id/parent_name repair nested rows; cover_image_id/igdb_id/igdb_platforms repin a wrong IGDB match), update_games_batch (the bulk repair loop — all single-item guards per item, one deferred affinity recompute, faithful `dry_run`), set_playtime (pins per-platform playtime_minutes/last_played in `game_platforms.manual_overrides` so syncs don't clobber; `clear` hands a column back to sync), set_playtime_batch, set_switch2_playtime_baseline (backfills pre-tracking Switch playtime: user enters the game's CURRENT Nintendo total in hours, synced daily minutes are subtracted, and the remainder lands as a synthetic `manual-baseline`/`1970-01-01` row in `nintendo_play_summary` so future syncs keep adding real days on top — deliberately NOT a set_playtime pin, which would freeze the SUM-recomputed switch2 total; re-runs replace the baseline, a total equal to synced removes it, `application_id` records the title id for never-synced games)
- `acquisition.py`: set_acquisition, set_acquisitions_batch (fill-only by default — re-imports never clobber manual edits; edition/upgrade-pack/SKU suffixes — ROW, "Store", "Base Game", bare "Ultimate"/"GOTY"; deliberately NOT "Complete", which names real compilations — stripped via `normalize_purchase_title`; nested content_type matches exact name only, no fuzzy; a fuzzy match refuses to CREATE a platform row when the matched row's parent/child family already owns that platform (`family_conflict` bucket) — no forked ownership inside a family; `dry_run` runs the identical matching path without writing, so preview counters are faithful), split_bundle_acquisition (records a multi-game bundle across constituents — even cent-preserving price split, `create_missing` mints new owned rows, `fuzzy=False` prevents collapsing a sequel), get_spending_stats (per-currency, never summed; by_family rolls each base game + its owned DLC/addons), import_purchases (orchestrates `data/purchases/` fetchers; per-source failures don't block others; multi-game bundles diverted to `bundles_needing_split` for split_bundle_acquisition; nested purchase items stay exact-match-only to prevent spend corruption; `create_missing` defaults **True** for minting new owned games from purchases, reported in `created`/`created_details`, but refuses two shapes into `unmatched` + `create_refused_details`: a nested record with no resolvable parent, and a primary title that is only an edition/alias variant of an existing row ("STRAFE: Millennium Edition" beside "STRAFE: Gold Edition"); bundle entries are deduplicated per (name, date, price, source) since one order carries a key per platform, and `already_recorded` is platform-agnostic; `set_acquisitions_batch`'s `create_missing` defaults False; compilation-named misses ("… Collection", "… Franchise Pack", "… Complete") divert to `bundles_needing_split` instead of minting phantom base games; Steam "N-Pack" SKUs are N copies of one game, stripped in the importer; zero-price free/gift misses land in `unmatched_free`, not `unmatched`; purchase_source vocabulary includes `key_reseller` with per-vendor aliases — GAMIVO/Kinguin/G2A/GMG/…; Humble subproducts whose downloads are all ebook/audio/video (Book Bundles) are excluded to `skipped`, key-delivery tails ("… Steam Key") stripped, and addon-named keys get a `content_type` hint via the shared `data/content.py::match_addon_name` table; Humble subscription plan payments (game-less "Annual Plan"/"Classic Plan" orders) are attributed across the zero-priced Choice drops via a FIFO month-credit queue — deliberately order-insensitive within the month because the drop's content order routinely predates its charge (reveal first Tuesday, auto-bill last Tuesday, buy-anytime since 2022))
- `integrations.py`: get_integration_status
- `scrape_admin.py`: scrape-heal implementations — get/diagnose/propose/approve/rollback_scrape_config, exposed as just two tools: `get_scrape_config(provider, diagnose=)` (read-only, open-world when diagnosing) and `manage_scrape_config(provider, action=)`. The split is on the read/write boundary on purpose — a merged tool takes the STRICTEST annotation it absorbs, so folding the read path in would advertise it as a non-idempotent mutation.
- `query.py`: query_library (free-form read-only SQL — SELECT/WITH/EXPLAIN/VALUES only, via a dedicated `data/db/readonly.py` connection locked down with `mode=ro` + an authorizer allowlisting only SELECT/READ/FUNCTION/RECURSIVE, plus a ~5s progress-handler timeout; 200-row cap, cell truncation at 300 chars, errors return `{"error", "sql", "hint"}` instead of raising), get_db_schema (live `sqlite_master`/PRAGMA introspection merged with this module's curated `TABLE_ANNOTATIONS`/`EXAMPLE_QUERIES`/`GUIDANCE` — semantic views `v_owned_games`/`v_game_playtime` (schema.py, switch2-correct playtime) plus live enum values for low-cardinality columns). Every `query_library` call is logged to `query_log` (success or error) via the normal RW connection, never the read-only one. `tests/test_query_tool.py`'s annotation-sync test is a strict two-way drift guard — every live table/view needs a `TABLE_ANNOTATIONS` entry and vice versa — so adding/renaming a table without updating the annotations fails CI.
- `common.py`: shared subqueries + platform-alias resolver. The three `_GAME_ROLLUP_CTE` variants deliberately stay in their own modules; they differ.
- `search.py`: tiered name-match SQL (exact > prefix > substring > token-AND over `name_normalized`) + fuzzy fallback; used by search, detail, and rate_game.
